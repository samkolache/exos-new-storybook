# Padding

Padding is the space inside a part, between its edge and its content. It uses the [Spacing](?path=/docs/foundations-spacing--docs) scale, with the rules below from IBM Carbon (sizes and padding) and Apple (touch). **Pick the height first; the padding follows from it.**

## The rules

| Part | Top and bottom | Sides | Examples |
|---|---|---|---|
| **Controls** | Set by the height (32, 40 or 48px) | 16px (`05`) | Buttons, inputs, segments, tabs |
| **Compact items** | Set by the height | 12px (`04`), 8px (`03`) when small | Chips, tags, badges |
| **Rows** | 12px (`04`) | 16px (`05`) | Menu items, list rows, upload items, card rows |
| **Small surfaces** | 8 to 16px | 12 to 16px | Tooltips (8 / 12), notifications and toggletips (16) |
| **Surfaces** | `--exos-space-inset`: 16px on phones, 24px on web | Same | Cards, panels |
| **Modals** | 24px on web, 16px on phones | Same | Modals and sheets |

Between an icon and its text: **8px** (`03`), or 4px (`02`) in small items like tags.

### Details

- **Borders count as padding.** A button with a 1px border has 15px of padding, so its text sits 16px from the edge: `calc(var(--exos-spacing-05) - 1px)`.
- **2px tighter beside an icon.** Icons carry their own space, so the side with an icon gets `calc(token - 2px)` to look even.
- **Phones: the 44px tap target wins.** Controls grow to at least 44px tall; their side padding doesn't change.
- **Never smaller than the scale.** If text feels cramped, use a bigger size, not custom padding.

## Usage

```css
.photo-row {
  padding: var(--exos-spacing-04) var(--exos-spacing-05); /* 12px 16px */
}

.photo-card {
  padding: var(--exos-space-inset); /* 16px on phones, 24px on web */
}
```
