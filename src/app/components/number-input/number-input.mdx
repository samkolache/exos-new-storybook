## Live demo

On a phone, tapping the field opens the number keypad. Switch the device to compare.

<DeviceCanvas of={NumberStories.Overview} defaultDevice="mobile" />

## When to use

**Use a number input** for amounts people might count up or down: quantities, guests, weights, percentages.

**Don't use it** for numbers that aren't amounts, like card, phone or order numbers: use an [Input](?path=/docs/components-forms-input--docs) with `inputMode="numeric"`. Nobody steps a card number with +.

### Compared with look-alikes

| Component | Use it for |
|---|---|
| **Number input** | Amounts, often small, often stepped: 1 to 10 tickets |
| [Input](?path=/docs/components-forms-input--docs) with `inputMode` | Numbers that are names or codes: card, phone, ZIP |
| [Select](?path=/docs/components-forms-select--docs) or [Chip](?path=/docs/components-chip--docs) | A few fixed amounts: 1, 2, 4 or 8 |

## Modifiers

<DeviceVariation title="Unit" of={NumberStories.ModUnit}>

`unit="%"` shows the unit after the number, so people only type the number. Screen readers hear "15 %".

</DeviceVariation>

<DeviceVariation title="Decimals" of={NumberStories.ModDecimals}>

`[decimals]="1"` allows decimals and opens the decimal keypad on phones. Pair it with a matching `step`, like 0.5.

</DeviceVariation>

<DeviceVariation title="Range" of={NumberStories.ModRange}>

`min` and `max` limit the number. Out of range, it says "Enter a number from 1 to 8" right away, and snaps back into range when people leave. Say the range in `helpText` too, so people know before they hit it.

</DeviceVariation>

<DeviceVariation title="No steppers" of={NumberStories.ModNoSteppers}>

`[hideSteppers]="true"` for numbers nobody steps through, like a year.

</DeviceVariation>

## Specs

Use **Small / Medium / Large**, **Help / Error** and **Mobile / Web** to see each case. Blue shows the padding inside the field. The numbers are measured from the code.

<SpecPictures of={NumberStories.SpecDrawing} />

- **Label to field:** 8px on every device.
- **Field to help or error text:** 4px on the web, 8px on phones, so the message reads as its own line under a taller field.
- **Help text** is grey and **error text** is red, both 14px. An error shows right under the field (above any help text), and the field gets a red border.
- Phones show a number keypad (with a decimal point when decimals are allowed). Numbers line up in columns.

## Content

- **Label: what's counted,** like "Guests" or "Weight".
- **Say the range in help text** when there is one: "Up to 8 per booking."
- **Use the unit,** not a label like "Weight (kg)".

## Behavior

### Keyboard

| Key | Does |
|---|---|
| <kbd>↑</kbd> / <kbd>↓</kbd> | Up or down one step |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | Up or down ten steps |
| <kbd>Home</kbd> / <kbd>End</kbd> | The minimum or maximum |
| Typing | Any number; checked as people type, snapped into range when they leave |

− and + aren't Tab stops: the arrow keys do the same, so keyboard users have one stop instead of three.

### Mobile and web

| | Mobile (below 672px) | Web (672px and up) |
|---|---|---|
| Space to help or error text | 8px | 4px |
| Label to field | 8px | 8px |
| Keyboard | Number keypad (decimal keypad with `decimals`) | A physical keyboard, with arrow keys |
| − and + | 44px wide | 36px wide |
| Height | At least 44px with 16px text | 32 / 40 / 48px |

See [Mobile and web](?path=/docs/foundations-mobile-and-web--docs).

## Accessibility

For the quantity in the live demo, a screen reader reads:

<ScreenReader name="Quantity" role="spin button" state="2" description="minimum 1, maximum 10" />

- **A spin button,** with its value, minimum and maximum, so screen readers say where it is in the range.
- **The out-of-range message** is linked to the field and read when it changes.
- **− and + have names:** "Decrease Quantity", "Increase Quantity".
- **Checked automatically:** every story runs an accessibility scan in the tests, plus stepping, range and reactive form tests.
