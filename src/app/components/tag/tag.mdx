## When to use

**Use a tag** to label something with a short fact people read but don't act on:

- Where an answer came from, like photos, voice notes or property records.
- A status, like "Needs your input" or "Waiting on photo".
- That the AI produced something.

### Compared with look-alikes

| Component | People can… | Use it for |
|---|---|---|
| **Tag** | Read it | Status or source labels |
| [Chip](?path=/docs/components-chip--docs) | Pick it | Answers to a question |
| [Button](?path=/docs/components-button--docs) | Press it | Actions |
| Plain text | Read it | Details too long or too important for a label |

| 1 | **Container** | Always. Fully rounded, 16, 20 or 26px tall. Its fill comes from the colour. |

## Variants

<DeviceVariation
  title="Color"
  of={TagStories.Switchable}
  switches={[{ arg: 'color', label: 'Color', initial: 'neutral', options: [
    { value: 'neutral', label: 'Neutral', short: 'N' },
    { value: 'blue', label: 'Blue', short: 'B' },
    { value: 'attention', label: 'Attention', short: 'A' },
    { value: 'info', label: 'Info', short: 'I' },
  ] }]}
>

Colour carries the meaning, so pick it by what the tag says. Use the switch in the toolbar; only `color` changes in the code.

- **Neutral** (default): plain facts, like "From order".
- **Blue:** AI. Usually set with `ai` instead (see Modifiers).
- **Attention:** something needs a person, like "Needs your input".
- **Info:** something is in progress, like "Waiting on photo".

</DeviceVariation>

## Size

<DeviceVariation title="Small, medium, large" of={TagStories.Switchable} sizeSwitch>

Use the switch in the toolbar. Only `size` changes in the code.

- **Small** (`sm`, 16px): dense web tables and lists. On phones it takes the medium size, so text is never under 11px.
- **Medium** (`md`, 20px, default): the Figma tag.
- **Large** (`lg`, 26px): next to large text, like a page title.

Icons scale with the size.

</DeviceVariation>

## Modifiers

One input each, so they work with any colour and size.

<DeviceVariation title="Icon" of={TagStories.ModIcon}>

A leading icon makes a tag faster to scan. Add `icon`, like `icon="calendar"`. Leave it out for text-only tags.

</DeviceVariation>

<DeviceVariation title="AI" of={TagStories.ModAI}>

Add `[ai]="true"` when the AI produced the answer. The tag turns blue with a sparkle. An `icon` you pass replaces the sparkle, like `icon="voice"` for voice notes.

</DeviceVariation>

<DeviceVariation title="Disabled" of={TagStories.ModDisabled}>

Add `[disabled]="true"` for things nobody needs to act on, like skipped steps. It greys out the tag and its icon, whatever the colour.

</DeviceVariation>

## Content

- **Keep labels to 1 to 3 words,** sentence case, no full stop. They are labels, not messages.
- **Say what it is, not what to do:** "Needs your input", not "Please check this".
- **Start source tags with where it came from:** "From order", "From property records".

<DoDont>
  <Guideline type="do" of={TagStories.DoShortLabel}>keep the label short enough to read at a glance.</Guideline>
  <Guideline type="dont" of={TagStories.DontSentence}>write a sentence. It gets cut off; use plain text instead.</Guideline>
  <Guideline type="do" of={TagStories.DoAttentionSparingly}>use attention only for what needs a person.</Guideline>
  <Guideline type="dont" of={TagStories.DontAllAttention}>make everything orange. Nothing stands out any more.</Guideline>
  <Guideline type="do" of={TagStories.DoOneTag}>give each item the one tag that matters most.</Guideline>
  <Guideline type="dont" of={TagStories.DontManyTags}>stack several tags on one item.</Guideline>
</DoDont>

## Behavior

### Interaction

Tags are labels, not controls. They can't be clicked, focused or reached with <kbd>Tab</kbd>. If people need to act on something, use a [Button](?path=/docs/components-button--docs) or a [Chip](?path=/docs/components-chip--docs).

### Mobile and web

See [Mobile and web](?path=/docs/foundations-mobile-and-web--docs).

| | Mobile (below 672px) | Web (672px and up) |
|---|---|---|
| Size | Small shows as medium: text is never under 11pt | Any; small fits dense tables |
| Long labels | Wrap onto a second line | End in an ellipsis, full text on hover |
| Placement | Under the item it labels, so it doesn't squeeze the content | Beside the item, on the same line |
| Many tags | Wrap onto a new line | Wrap onto a new line |

### Edge cases

<SpecimenGrid>
  <Specimen of={TagStories.EdgeLongLabel}>**Long label:** on web it ends in an ellipsis with the full text in the tooltip; on phones it wraps.</Specimen>
  <Specimen of={TagStories.EdgeWrap}>**Narrow space:** tags wrap onto a new line instead of shrinking.</Specimen>
  <Specimen of={TagStories.EdgeNoIcon}>**No icon:** the padding evens out on both sides.</Specimen>
</SpecimenGrid>

## Accessibility

For the AI tag in the live demo, a screen reader reads:

<ScreenReader name="AI Photos" role="text" state="no state (not interactive)" />

- **Colour is never the only signal:** the label says what the tag means, and AI tags include "AI" in what is read.
- **Decorative icons are hidden** from screen readers. Only the AI sparkle is announced.
- **Contrast:** every colour passes 4.5:1 for its text. The info text is a shade darker than the Figma blue to get there.
- **Checked automatically:** every tag story runs an accessibility scan in the tests, and a test checks the text above.
