## Live demo

On the web, the calendar button opens a calendar under the field. On a phone, tapping the field opens the phone's own date picker. Switch the device to compare.

<DeviceCanvas of={DateStories.Overview} defaultDevice="mobile" />

## When to use

**Use a date picker** for a date in the near past or future, where seeing the calendar helps: deliveries, bookings, appointments.

For dates people know by heart and that are far away, like a date of birth, a calendar means a lot of scrolling. Use it with `max` and let people type, or use three [Inputs](?path=/docs/components-forms-input--docs) for day, month and year.

### Why it's the browser's own date field

The calendar is the browser's and the phone's own, so:

- **On phones,** people get the date picker they use everywhere else.
- **Dates show in each person's format,** like 20/11/2026 or 11/20/2026, while your code always gets `'2026-11-20'`.
- **Keyboards and screen readers** already know how to use it.

## Modifiers

<DeviceVariation title="Earliest and latest" of={DateStories.ModRange}>

`min` and `max` (ISO dates) grey out the dates outside the range in the calendar. Say the range in `helpText` too.

</DeviceVariation>

<DeviceVariation title="Start and end dates" of={DateStories.ModRangePair}>

For a range, use two pickers. Set the second one's `min` to the day after the first, and show the length in its help text, like "2 nights".

</DeviceVariation>

<DeviceVariation title="Optional" of={DateStories.ModOptional}>

</DeviceVariation>

## Specs

Use **Small / Medium / Large**, **Help / Error** and **Mobile / Web** to see each case. Blue shows the padding inside the field. The numbers are measured from the code.

<SpecPictures of={DateStories.SpecDrawing} />

- **Label to field:** 8px on every device.
- **Field to help or error text:** 4px on the web, 8px on phones, so the message reads as its own line under a taller field.
- **Help text** is grey and **error text** is red, both 14px. An error shows right under the field (above any help text), and the field gets a red border.
- Phones open their own date picker; web shows the browser's calendar under the field.
- Dates appear in the format the person's device uses.

## Content

- **Label: what the date is for,** like "Delivery date" or "Check in".
- **Say the limits** in help text: "From tomorrow until Dec 31."
- **Don't explain the format.** The field already shows it the way each person reads dates.

<DoDont>
  <Guideline type="do" of={DateStories.DoLimitDates}>limit the dates people can pick, and say so.</Guideline>
  <Guideline type="dont" of={DateStories.DontFreeText}>ask people to type a date in a format you choose.</Guideline>
</DoDont>

## Behavior

### Keyboard

| Key | Does |
|---|---|
| <kbd>Tab</kbd> | Into the field, through day, month and year |
| <kbd>↑</kbd> / <kbd>↓</kbd> | Changes the focused part |
| Numbers | Type the date directly |
| <kbd>Space</kbd> or the calendar button | Opens the calendar (web) |

### Mobile and web

| | Mobile (below 672px) | Web (672px and up) |
|---|---|---|
| Space to help or error text | 8px | 4px |
| Label to field | 8px | 8px |
| Opens | The phone's own date picker | A calendar under the field |
| Typing | Through the picker | Directly, or with the calendar |
| Height | 44 / 48 / 48px with 16px text | 32 / 40 / 48px |

See [Mobile and web](?path=/docs/foundations-mobile-and-web--docs).

## Accessibility

For the picked date in the live demo, a screen reader reads:

<ScreenReader name="Check in" role="date field" state="20 November 2026" />

- **The browser's own date field,** so screen readers read each part (day, month, year) and the date in full.
- **Labels, help and messages** are linked like every field.
- **Checked automatically:** every story runs an accessibility scan in the tests, plus value and reactive form tests.
